01 · At a glance

Explainer videos as code

Pi & Pixel wraps the Manim animation engine in a browser studio. You write (or later, generate) a scene, preview it, apply a brand, and export every format you need from one project.

The problem

  • 3Blue1Brown-style animation needs Python, Manim, FFmpeg and LaTeX set up correctly.
  • Rendering is heavy on RAM and CPU, so weak laptops struggle.
  • Every format (YouTube, Reels) and every client brand means manual re-work.
  • Hosting render servers before the product is validated is expensive.

The solution

  • A studio in the browser: editor, live preview, logs, brand kits, export gallery.
  • Rendering runs on the user's compute: their PC, Docker or Google Colab.
  • One project produces many videos × formats × brands × languages.
  • The same render core later runs on our servers inside ReelMVP.

Five ideas that define the product

🖥️

Bring your own compute

The browser only controls. All heavy work happens where the Agent runs: laptop, Docker or Colab.

π

Manim stays Manim

Scenes are plain Manim Python. No hidden engine, no lock-in. They also run with the normal manim command.

🎨

Brand kits

Logo position, size, opacity and timing, plus colours and fonts. Moving a logo never re-renders the animation.

🧩

Many videos, many variants

Compositions × formats × brands × parameters. Shared scenes are rendered once and reused.

🚚

ReelMVP-ready

The pipeline is a headless library plus a CLI. ReelMVP's servers will run the same code.

🤖

AI when useful

Later: Claude generates and fixes scenes. Its code is always shown as a diff and never auto-runs.

03 · Architecture

The browser controls. Your machine renders.

Two parts: the Studio (a web page) and the Agent (a Python program on the compute target). Video data never travels through our servers.

04 · Branding

Brand kits: the logo exactly where you want it

Each brand kit holds a logo with its placement rules, a colour theme and a font. Placement can differ per format, so a reel can keep the logo clear of the app's buttons.

What you control

SettingOptions
Logo filePNG with transparency, or SVG (≤ 5 MB)
Anchor9-point grid or custom x / y
Size, margin% of frame width / shorter edge
Opacity0–100%
TimingFrom / until, optional fade
Per formatDifferent rules for 16:9, 9:16, 1:1
ThemeBackground, primary, secondary, accent, text colours; font
LaterWatermark, intro/outro, safe-zone auto-nudge

What a change costs

You changeManim re-render?
Logo position / size / opacityNo FFmpeg only
Clip order, musicNo FFmpeg only
Brand colours / fontYes affected scenes
Scene code, params, formatYes affected scenes
The logo is added at the very end, in the same FFmpeg pass that joins the scenes. Re-positioning it takes one quick encode instead of re-drawing every animation.

05 · Multiple videos and variations

One project. Every video you need.

A project holds several compositions (videos), each an ordered list of scenes. An export multiplies them across formats, brands and parameters such as language. Shared work is done once.

4 videos

2 formats × 2 brands of the main composition.

6 Manim renders, not 12

The brands share a theme, so each scene is drawn once per format and reused.

0 renders to move a logo

Only the 4 quick FFmpeg composites re-run.

How an export is described

# pnp.yaml (excerpt)
compositions:
  main:   { clips: [ intro.py:Intro, proof.py:Proof, outro.py:Outro ] }
  teaser: { clips: [ proof.py:Proof ], params: { title: "Why a² + b² = c²" } }

variants:
  matrix:
    composition: [main, teaser]
    format:      [landscape, portrait]     # 16:9, 9:16 (1:1 also built in)
    brand:       [default, acme]
    params: { lang: [en, hi] }              # every parameter multiplies the set
  exclude: [ { composition: teaser, format: landscape } ]
  max: 24                                   # safety cap

Before anything runs, the Studio shows the number of videos, the number of unique renders, and how many are already cached. You confirm, then it renders.

06 · Rendering pipeline

From code to a checked MP4

Every export follows the same nine steps. A failure at any step is logged and cleaned up, and the last good video is never overwritten.

A scene is plain Manim

from manim import *
from pnp import ctx   # format, theme, params

class Proof(Scene):
    def construct(self):
        self.camera.background_color = ctx.theme.background
        title = Text(ctx.params.get("title", "a² + b² = c²"),
                     color=ctx.theme.primary)
        # one scene, responsive to 16:9 and 9:16
        title.to_edge(UP if ctx.format.is_portrait else UL)
        self.play(Write(title))

Without Pi & Pixel, ctx falls back to defaults, so manim -ql proof.py Proof still works.

Safety and reliability

  • User code never runs inside the Agent. Each render is a separate process with time, memory and process limits; cancel kills the whole tree.
  • Locked down by default. The Agent listens only on 127.0.0.1 and every request needs a random token.
  • Secrets stay out. Tokens and AI keys never reach the browser or the render process.
  • No fake progress bars. Only measured counts and percentages are shown.
  • Reproducible. Each video records its source revision and engine versions.
  • Crash-safe. Jobs survive restarts; interrupted jobs (e.g. a Colab disconnect) can be retried.
  • Low-RAM aware. The scheduler runs fewer jobs at once when memory is short.

Tech stack, risks and the road to ReelMVP

Tech stack

AreaChoice
AnimationManim Community Edition (pinned)
MediaFFmpeg 6+, ffprobe
Maths textLaTeX (TeX Live subset / TinyTeX), optional
BackendPython 3.12, FastAPI, Pydantic v2
StorageSQLite (WAL) via stdlib sqlite3 + numbered SQL migrations; files / Drive
Job queueOwn SQLite queue (no Redis in MVP)
FrontendReact, TypeScript, Vite, Tailwind
Editor, terminalMonaco, xterm.js
Qualityruff, pyright, pytest, ESLint, Vitest, Playwright
Packaginguv / pnp CLI, Docker, Colab notebook
AI (later)Claude API behind a small interface

Main risks

RiskMitigation
Colab's terms restrict some web UIs on the free tierUse Colab's own proxy, check the terms in Cycle; fall back to paid Colab or local
8 GB laptops run out of memoryDraft quality first, RAM-aware scheduling, benchmarked limits
LaTeX install is slow on Colab"Skip LaTeX" option, cached install on Drive
16:9 scenes look wrong on 9:16ctx.format helpers, responsive starter scenes, gallery review
Too many variants at oncePlan preview, confirmation, cap of 24
Imported projects contain harmful codeProcess limits now; Docker sandbox with no network later

Future: server mode inside ReelMVP

Unchanged: pnp_core, the scene SDK, the project format, the job spec and the Studio components. Swapped: SQLite → Postgres, local queue → Redis/SQS, disk → S3, single user → multi-tenant accounts, and sandboxing becomes mandatory.
